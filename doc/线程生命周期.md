# 线程生命周期
线程生命周期描述的是一个**线程对象**从被创建、参与调度、执行入口函数、不再参与调度和被其他线程观察到线程已经 `dead` 的过程。

## 生命周期状态
NerdRTOS 使用 `nd_thread_stat_t` 描述线程在内核中的生命周期状态:

```c
typedef enum {
    ND_THREAD_STAT_INIT = 0,
    ND_THREAD_STAT_READY,
    ND_THREAD_STAT_RUNNING,
    ND_THREAD_STAT_BLOCK,
    ND_THREAD_STAT_SUSPEND,
    ND_THREAD_STAT_DEAD,
} nd_thread_stat_t;
```

各种状态含义如下：
- `ND_THREAD_STAT_INIT`：线程控制块被初始化，但未参与调度。
- `ND_THREAD_STAT_READY`：线程具备运行条件，位于就绪队列中，等待调度器执行。
- `ND_THREAD_STAT_RUNNING`：线程正在运行。
- `ND_THREAD_STAT_BLOCK`:线程正在等待某个条件成立，如信号量、互斥量。
- `ND_THREAD_STAT_SUSPEND`:线程被挂起，期间不参与调度，被 `resume` 才会重新进入可调度状态。
- `ND_THREAD_STAT_DEAD`：线程生命周期结束，不再参与调度。

## 线程创建
在 NerdRTOS 中，线程创建是把一块尚未被内核管理的线程控制块(`nd_thread_t`)和一各外部提供的内存空间，初始化成一个参与调度的线程。

NerdRTOS 中线程创建通过 `nd_thread_create()` 完成：

```c
nd_err_t nd_thread_create(nd_thread_t   *thread,
                          const char    *name,
                          void          (*entry)(void *parameter),
                          nd_uint8_t    priority,
                          void          *parameter,
                          void          *stack,
                          nd_size_t     stack_size,
                          nd_uint32_t   options,
                          nd_uint64_t   time_slice);
```

创建流程可以分为两个阶段：线程对象初始化和加入调度系统。

### 线程对象初始化

线程对象初始化由 `nd_thread_init()` 完成。这个阶段线程还没有参与调度，状态处`ND_THREAD_STAT_INIT`。初始化的核心任务是把线程控制块中的各个字段设置为一致、可管理的初始状态。

主要包括以下内容：

- 保存线程入口函数和入口参数：`entry`、`parameter`
- 保存线程优先级：`priority`、`init_priority`
- 保存栈空间信息：`stack_addr`、`stack_size`
- 初始化阻塞等待用的定时器：`timer`
- 初始化时间片相关字段：`slice`
- 初始化链表节点：`qnode`、`tlist`、`join_list`
- 初始化互斥量和事件相关上下文：`mutex`、`event`
- 使用 `0xAA` 填充线程栈，用于后续栈使用量统计
- 调用 `nd_hw_stack_init()` 构造线程初始上下文

### 加入调度系统
线程对象初始化完成后，`nd_thread_create()` 会把线程状态从 `ND_THREAD_STAT_INIT` 切换为 `ND_THREAD_STAT_READY`，表示该线程已经具备运行条件。

随后线程会被加入两个链表：

- `nd_thread_list`：全局线程链表，用于遍历系统中存在的线程对象。
- `ready queue`：调度器使用的就绪队列，用于选择下一个要运行的线程。

加入 `ready queue` 后，`nd_thread_create()` 会调用 `nd_scheduler()`。

## 线程入口
NerdRTOS 的入口包装函数是 `nd_thread_entry`:
```c
void nd_thread_entry(void (*entry)(void *), void *parameter)
{
    entry(parameter);

    nd_thread_abort(nd_current_thread);
}
```

线程第一次运行的时候，真正进入的是 `nd_thread_entry`, 用户入口函数在里面被调用。`nd_thread_entry` 为用户入口函数提供了一个确定的生命周期边界，用户线程可以通过 `return` 表示结束，内核会对线程 `abort` 也就是让线程不再参与调度。

## 线程终止
线程终止表示线程的调度生命周期结束。一个线程一旦进入终止状态，就不应该再被调度器选择运行，也不应该继续留在 `ready queue` 或等待队列中。

NerdRTOS 通过 `nd_thread_abort` 来实现线程终止：
```c
nd_err_t nd_thread_abort(nd_thread_t *thread)
{
    nd_kernel_def();
    nd_kernel_lock();

    if (!thread) {
        nd_kernel_unlock();
        return ND_EINVAL;
    }

    if (nd_is_thread_dead(thread)) {
        nd_kernel_unlock();
        return ND_EOK;
    }

    if (nd_is_thread_essential(thread)) {
        nd_kernel_unlock();
        return ND_EPERM;
    }

    nd_thread_halt(thread);

    nd_kernel_unlock();

    return ND_EOK;
}
```

线程终止有两种来源：
- 线程入口函数执行结束，由 `nd_thread_entry()` 调用 `nd_thread_abort(nd_current_thread)` 终止当前线程。
- 线程主动调用 `nd_thread_abort(thread)` 终止目标线程。

线程结构体有 `options` 字段，用于描述线程的生命周期属性或特殊行为。当前 NerdRTOS 支持的选项有：
```c
typedef enum {
    ND_THREAD_OPT_NONE      = 0u,
    ND_THREAD_OPT_ESSENTIAL = (1u << 0),
} nd_thread_option_t;
```

其中 `ND_THREAD_OPT_NONE` 表示为普通线程， `ND_THREAD_OPT_ESSENTIAL` 表示关键线程。关键线程不允许被 `abort` ，如果试图 `abort` 选项有 `ESSENTIAL` 的线程会被拒绝并且返回 `ND_EPERM`。

## 线程结束等待
`join` 用于等待目标线程的生命周期结束。用于判断目标线程是否已经进入`ND_THREAD_STAT_DEAD` 状态。

NerdRTOS 通过 `nd_thread_join()` 实现线程结束等待：
```c
nd_err_t nd_thread_join(nd_thread_t *thread, nd_uint64_t timeout)
{
    nd_kernel_def();
    nd_kernel_lock();

    if (!thread) {
        nd_kernel_unlock();
        return ND_EINVAL;
    }

    if (thread == nd_current_thread) {
        nd_kernel_unlock();
        return ND_EDEADLK;
    }

    if (thread->stat == ND_THREAD_STAT_DEAD) {
        nd_kernel_unlock();
        return ND_EOK;
    }

    if (timeout == ND_TIMEOUT_NOWAIT) {
        nd_kernel_unlock();
        return ND_EBUSY;
    }

    nd_thread_pend(&thread->join_list, timeout);

    nd_scheduler();

    nd_kernel_unlock();

    return nd_current_thread->error;
}
```

`nd_thread_join` 的处理流程有两类：
- **立即返回**:
  - 如果目标线程已经是 `ND_THREAD_STAT_DEAD`,说明目标线程已经结束，立即返回 `ND_EOK`。
  - 如果目标线程尚未结束，并且 `timeout == ND_TIMEOUT_NOWAIT`,说明调用者只想检查状态不愿意等待，立即返回 `ND_EBUSY`。

**因此 `join` 也可以用于判断线程是否已经 `dead`。**

- **阻塞等待**：如果线程目标尚未结束，且`timeout != ND_TIMEOUT_NOWAIT` 时，当前线程会挂入目标线程的 `join_list`。

## 生命周期与内存所有权
NerdRTOS 中，无论是 `create` ，`abort` 或者 `join`，都仅仅负责修改线程的生命周期，不负责自动分配或释放线程控制块与线程栈。线程控制块和线程栈由调用者提供。

用户创建线程需要提供两类内存：
- 线程控制块
- 线程栈

这两类内存可以选择静态分配或者动态分配，由调用者自己决定。

对于**动态分配的线程**，调用者应当确认线程状态为`ND_THREAD_STAT_DEAD`后，释放线程栈和线程控制块。
